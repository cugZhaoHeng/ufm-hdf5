`FuncAnimation` 是 `matplotlib.animation` 模块的核心。它的本质是一个**定时器驱动的循环渲染器**。

以下是关于它的实现原理及 `update` 函数规则的详细说明：

### 1. `FuncAnimation` 的实现原理
`FuncAnimation` 并不像视频编辑软件那样“生成”一个视频流，它的工作流程如下：

1.  **初始化 (Setup)**：首先绘制第一帧（或者在 `init_func` 中定义的初始状态）。
2.  **循环触发 (Looping)**：它通过 Python 的 `Timer` 或者后端特定的事件循环，按照设定的 `interval`（毫秒）间隔，反复调用你提供的 `update` 函数。
3.  **重新绘制 (Redraw)**：
    *   在每一帧调用时，`update` 函数会根据传入的 `frame` 参数，修改图形对象的数据（比如调用 `set_data`, `set_verts`, `set_text` 等）。
    *   Matplotlib 会在该帧结束后，将改变后的图形进行一次**渲染（Render）**。
4.  **Blitting (可选)**：如果设置 `blit=True`，它会进行“位块传输”（Bit Block Transfer）。这是一种优化技术，只重绘图形中改变的部分，而不是重绘整个画布（背景、坐标轴等），从而大幅提升动画速度。

---

### 2. `update` 函数的固定模式
`update` 函数必须遵循以下模式才能保证动画正常工作：

#### A. 参数要求
*   **第一个参数**：必须接收一个参数（通常命名为 `frame` 或 `frame_idx`），这个参数由 `FuncAnimation` 的 `frames` 迭代器提供。
*   **后续参数**：如果你有额外的数据（如你的代码中用到的 `poly_collections` 或 `title`），通常通过**闭包（Closure）**的方式（即在函数外部定义并在内部引用）传递，或者通过 `fargs` 参数传递。

#### B. 返回值要求
**`update` 函数必须返回一个包含“被修改过的图形对象”的迭代器（通常是 list 或 tuple）。**

*   **为什么需要返回值？** 
    如果你启用了 `blit=True`，Matplotlib 需要知道这一帧里**哪些对象发生了变化**。它会将这些对象放入缓存，在下一帧只重绘这些对象。如果你不返回或返回空列表，`blit` 模式下动画将是一片空白（因为 Matplotlib 认为没有任何东西改变）。
*   **如果设为 `blit=False`？**
    虽然 `blit=False` 时即使不写 `return` 动画也能动（因为它会强制重绘全图），但**强烈建议写上返回值**，这符合规范，也保证了代码在切换 `blit` 模式时的兼容性。

---

### 3. 代码中的最佳实践示例

你的代码中这部分做得很好：
```python
def update(frame_idx):
    # ... 修改数据逻辑 ...
    # 必须返回所有被修改的图形对象列表
    return poly_collections + [title]
```

**常见的错误写法（会导致报错或动画不更新）：**
1.  **修改数据但没有 `set_` 方法**：比如你不能简单地写 `data = new_data`，必须使用类似 `line.set_data(...)` 或 `poly.set_verts(...)` 这样的方法来原地更新对象。
2.  **忘记返回列表**：如果 `return` 的不是列表，或者漏掉了某个需要更新的对象，那么该对象将不会在屏幕上更新。
3.  **在循环中重复添加对象**：千万不要在 `update` 函数里使用 `ax.plot()` 或 `ax.add_collection3d()`。这会在每一帧都添加一个新的线条，导致内存爆炸和图形混乱。**对象必须在外部创建一次，在 `update` 里只更新对象内部的数据。**

### 总结
*   **原理**：定时触发 `update` -> 更新图形数据对象 -> 触发局部或全局重绘。
*   **update 核心规则**：
    1.  入参：第一个参数必须是 `frame` 数据。
    2.  内部操作：仅使用 `set_` 类方法更新属性，**禁止创建新对象**。
    3.  出参：必须返回所有更新过的图形对象组成的列表。
